# イベントごとの共有カウンター

会場名を入力してカウンターを作ると共有URLが発行され、そのURLを開いたスタッフだけが同じ現在人数を見て、チェックインを積み上げられるようにする。

## 意図

イベント会場のスタッフが、自分のイベントの来場者数だけを各自の端末で数えたい場面で使う。

現在のカウンターは全世界で1つしかなく、無関係な誰かがチェックインを押すと自分の画面の数字も増える。来場者数を数えるという本来の用途では、自分のイベントの数だけが見えないと使えない。会場ごとにカウンターを分け、共有URLを知るスタッフの端末だけが同じ数字を見る形にする。

個人認証は導入しない。URLを知っている人が使えるという匿名共有の性質は今のまま保つ。

## 受け入れ条件の種

- ルートを開くと会場名の入力フォームだけが表示され、人数とチェックインボタンは表示されない
- 会場名を入力して作成すると共有URLに遷移し、その共有URLを画面上でコピーできる
- 共有URLを別ブラウザ（別セッション）で開くと、同じ会場名と同じ現在人数が表示される
- 別々に作成した2つのカウンターは互いに影響せず、片方でチェックインしても他方の人数は変わらない
- 存在しないIDの共有URLを開くと、見つからない旨が表示され人数は表示されない

## 実装メモ

- 共有URLは `#/r/<id>` のハッシュ形式にする。実パスにすると存在しないアセットを `index.html` へ返すフォールバック設定が必要になり `wrangler.jsonc` に手が入るため
- ID は `crypto.randomUUID().slice(0, 8)`
- 既存のグローバルなチェックイン記録は移行しない（本番のカウントは0件）
- `/api/health` の挙動は変えない。kojo の機械検証が依存している
- 会場の作成にも入力サイズ上限・バリデーション・レートリミットを付ける。無いと空のカウンターが量産される
- チェックイン数の集計は現在も `kv.list` の prefix 走査なので、prefix に会場IDを含める形にすれば構造は変わらない
